Research question

What does the architecture change?

“To what extent do a monolithic system prompt structure, a modular rule provision and a graph-based orchestration differ in terms of domain correctness, hallucination behaviour, decision stability and traceability in the automated validation and correction of structured JSON data in a production-critical environment?”

Translated from the German original.

Three variants
  • Monolithic system prompt
  • Modular rule cards
  • Graph orchestration
Four dimensions
  • Domain correctness
  • Hallucination behaviour
  • Decision stability
  • Traceability
Abstract

The result in one paragraph.

Two architectures were compared in three measurement conditions: 17 test cases with 29 changes defined by error injection, each run five times – 255 measurement runs. Three of the four dimensions show only small differences. The larger jump in correctness comes from the switch to modular rule provision, not from the graph. Across all runs, a single new error occurred in the target system.

The difference becomes clear in traceability: only the graph-based variant produces coherent execution and provenance information that allows individual correction decisions to be reconstructed.

The study

Graph or monolith? An empirical comparison.

Three measurement conditions, each differing in exactly one property – same model (GPT-4.1, temperature 0.3), same test cases, same environment. Errors were injected into real snapshots in a controlled way, so the correct fix was known in advance. Code and measurement procedures were frozen before the measurement.

Why this matters: only 9.1% of 88 studies on industrial LLM agents report evidence from real-world deployment (Henkel et al., 2026).

Path-exact only counts corrections made exactly at the expected JSON element. Functional counts whether the expected state was reached – including via a parent path. The largest jump comes with the switch to modular rule cards (A → B: +12 path-exact), not with the graph (B → C: −5).

Hallucination behaviour Wrong ≠ hallucinated

In every condition, 15 changes deviated from the reference value – and were nevertheless supported by the data provided. A metric that equates the two would have wrongly counted them as hallucinations.

Decision stability 14 · 15 · 14 of 17 stable

Stable does not mean correct: 9 · 9 · 8 of these cases were stable, but not fully correct in any repetition.

Follow-up errors 1 new error in 255 runs

Across all measurement runs, exactly one new error occurred in the target system.

Traceability 81 of 85 runs

Only the graph variant records a coherent execution and provenance trace. By design, there is no equivalent for A and B.

Targeted knowledge improves the correction.
Structured flows create traceability.

Under the conditions examined, the larger quality difference came from the targeted provision of relevant rules. Graph-based orchestration mainly enabled a better reconstruction of the processing steps.
For practice

Knowledge first, then structure.

For better results, check the rule provision first. Use graph orchestration specifically where traceability is required.

Methodology

Measure separately, report together.

Assess correctness and hallucination separately; report path-exact and functional evaluation together.

Scope

What transfers is the approach.

Not the result: one system, one language model, 17 domain-specific test cases. Next steps are a 2×2 design and longer trials in operation.
